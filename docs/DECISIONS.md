# Decisions

One line per architecture decision, newest last. Format: `ADR-NNN (YYYY-MM-DD): decision — rationale`.

- ADR-001 (2026-10-01): Tokens ship as plain CSS in cascade layers — no build step for consumers; `@layer fe-interview-design-system.{reset,tokens,base,utils}` keeps precedence explicit and lets unlayered consumer CSS always win.
- ADR-002 (2026-10-01): Stylelint owns SCSS, Biome owns CSS + JS/TS — Biome can't parse SCSS; Stylelint no longer covers `.css`, avoiding double lint/format conflicts (Biome lineWidth 100 vs Stylelint 120).
- ADR-003 (2026-10-01): Breakpoints via Sass `bpFrom` mixin + `$breakpoints` map, not `@custom-media` — Vite 8 dropped PostCSS plugin support, so `postcss-custom-media` can't run; Sass compiles media queries natively.
- ADR-004 (2026-10-01): Sass tooling (`bpFrom`, `useType`) ported from hanzo ecommerce-ui-library with modern `@use`/`@forward` modules — `@import` is deprecated for removal in Dart Sass 3.
- ADR-005 (2026-10-01): Typesets limited to `body-m`/`body-s`, non-responsive and bold — the two typesets actually needed; per-breakpoint/elastic machinery from hanzo deliberately not ported.
- ADR-006 (2026-10-01): Inter font via Google Fonts CDN `<link>` in `.storybook/preview-head.html`, weight 700 only — matches the bold-only typography intent; self-hosting deferred.
- ADR-007 (2026-10-01): Token values referenced as `var(--*)` inside Sass config — typesets stay in sync with tokens without a compile-time dependency between `tools/` and tokens.
- ADR-008 (2026-10-01): Storybook preview loads the full design-system stylesheet. Assumption: consuming apps import the same stylesheet and reconcile it with their own reset/base via cascade layers.
- ADR-009 (2026-10-02): Component variants styled via `data-*` attributes + semantic tokens, not modifier classes — first established by Badge (`data-tone` reacted to in SCSS via `--badge-*` custom properties); keeps variant mapping out of TS, styles declarative, and tokens swappable. Badges/status visuals are decorative only: text must be self-sufficient (WCAG 1.4.1) and `aria-label` avoided on generic-role spans. Multi-breakpoint tokens define `{name}-mobile` / `{name}-desktop` plus a runtime `--{name}` reassigned per breakpoint via `bpFrom` — mobile is the explicit default; rules read only the runtime `--{name}` and never the breakpoint-specific pair directly.
- ADR-010 (2026-10-05): Token layer partially migrated to Sass — spacings, borders, and font sizes compile through `src/styles/tools/spacing/px-to-rem`; color and easing token files keep plain-CSS custom-property syntax but compile as Sass modules through `index.scss`. Partial reversal of ADR-001; justified because Sass toolchain was already required for `bpFrom`/`useType` (ADR-003, ADR-007), so no new consumer dependency is introduced.
- ADR-011 (2026-10-05): Color token layer renamed to a scale-driven schema — primitives renamed to numbered scales (`color-ink` → `blue-9`, `color-surface` → `gray-1`, etc.) and semantic aliases renamed to a `color-{role}` family (`fg-default` → `color-text-primary`, `bg-default` → `color-background`, `border-default` → `color-border`, `tone-neutral/positive/negative` → `color-success`/`color-error` plus `color-text-on-status` for fills that stay pale in any theme). BREAKING for prior token consumers; establishes the precedent that primitives = scales, semantics = role names.
- ADR-012 (2026-10-05): `Badge` API takes React `children` instead of a `text` prop — use-the-platform; consumers compose icons or links without a second prop slot. BREAKING for prior `text` consumers.
- ADR-013 (2026-10-05): Motion tokens consolidated in `tokens/motion.scss` (`--speed-*` durations + `--curve-*` timing curves) — single canonical motion file; legacy semantic `--transition-*` tokens in `easing.scss` are deprecated and slated for removal in a dedicated refactor. First consumer: Tab transitions.
- ADR-014 (2026-10-05): `Tab` replaces the generic `trailing` slot with a Badge-shaped `badge?: { tone?, label }` prop and renders `Badge` internally — the AC ("add a Badge using the Tab's API") calls for a Tab-native abstraction, not a generic slot; `tone` reuses the exported `BadgeTone` so the union has one definition; `label` stays `ReactNode` per ADR-012 so composed content still works. BREAKING for prior `trailing` consumers.
- ADR-015 (2026-10-06): `Tabs` owns selection state (uncontrolled: internal `selectedId`, `defaultSelectedId` prop, `onChange(id)`) and implements the full WAI-ARIA APG tabs pattern — roving tabindex (`Tab` keeps `isSelected ? 0 : -1`), `←`/`→` move focus and selection with automatic activation and wrapping, `Home`/`End` jump, click selects. Matches the APG default and the majority-library consensus (MUI, Radix, React Aria, Headless UI); natural tab order was rejected (costs N tab presses on long tablists) and manual activation (Carbon-style) rejected because a generic primitive cannot assume expensive panels. Panels and `aria-controls` remain the consumer's responsibility.
- ADR-016 (2026-10-06): Focus indicators styled with `:focus-visible`, not `:focus` (first applied in `Tab.module.scss`) — keeps the ring for keyboard-driven focus, including programmatic `.focus()` inside keydown handlers (the roving arrow navigation), while suppressing it after pointer clicks; verified with real CDP key/mouse events. Matches native browser heuristics; WCAG 2.4.7 still satisfied.
